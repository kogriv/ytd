## Принципы и рамки

1. **Поведение пользователя не меняется** нигде, кроме явного исправления зависания (D-1). Все остальные изменения — внутренние либо документационные.
2. **Платформенная развилка — как можно позже.** Сначала проверяется свойство среды (интерактивен ли stdin), и только потом выбирается платформенный механизм чтения клавиш.
3. **Тесты не подстраивают продукт под себя.** Если тест падает из-за платформенного предположения в самом тесте — правится тест (D-2), а не нормализация путей в продукте.
4. **Рефакторинг без изменения контрактов.** Декомпозиция (D-4) не трогает публичный CLI, exit-коды и формат вывода; зелёные regression-тесты — критерий эквивалентности.
5. **Необратимые операции — только по явному решению владельца.** Переписывание git-истории (D-6) не выполняется в рамках спринта, а выносится отдельным решением.

Вне рамок этого дизайна: фичи из `devplan` (параллельная загрузка, GUI, планировщик), пересмотр модели «JSONL + SQLite» (GAP-CR-009, осознанный design debt).

## D-1. Кроссплатформенное ожидание возобновления (GAP-CR-026)

### Проблема

`wait_if_paused` выбирает бэкенд по `sys.platform`, а проверка не-интерактивного stdin есть только в Unix-ветке. На Windows без TTY процесс уходит в бесконечный `msvcrt.kbhit()`.

### Решение

Поднять проверку интерактивности на уровень `wait_if_paused` — до платформенной развилки. Обе ветки становятся симметричными, а дублирующая проверка в `_wait_for_resume_unix` удаляется как избыточная.

```python
# ytd/pause.py

def wait_if_paused(self) -> None:
    """Если пауза запрошена, показать промпт и ждать нажатия клавиши возобновления."""
    if not self._pause_requested.is_set():
        return

    safe_echo("\n" + "-" * 60)
    safe_secho("[PAUSE] ПАУЗА", fg=typer.colors.YELLOW, bold=True)
    safe_echo("-" * 60)
    if self.intra_video:
        safe_echo("Загрузка приостановлена. Частичный файл сохранён — продолжение с места остановки.")

    if not self._stdin_is_interactive():
        # Без TTY клавиши недоступны на любой платформе — единый безопасный fallback
        safe_secho(
            "Нажмите Enter для возобновления (stdin не интерактивный терминал)...",
            fg=typer.colors.CYAN,
        )
        self._wait_for_resume_prompt()
        return

    safe_secho(
        f"Нажмите '{self.resume_key}' для возобновления или Ctrl+C для выхода...",
        fg=typer.colors.CYAN,
    )
    if sys.platform == "win32":
        self._wait_for_resume_windows()
    else:
        self._wait_for_resume_unix()
```

Изменения в приватных методах:

- `_wait_for_resume_unix` — убрать проверку `if not self._stdin_is_interactive()` (теперь она выше по стеку);
- `_wait_for_resume_windows` — оставить `try/except ImportError` как страховку для не-Windows окружений с тем же `sys.platform`;
- `_wait_for_resume_windows` — заменить `threading.Event().wait(timeout=0.1)` на ожидание на `self._stop_listener`, чтобы `disable()` мог разорвать цикл (устраняет второй потенциальный источник зависания при завершении).

### Почему не альтернативы

| Альтернатива | Почему отвергнута |
|--------------|-------------------|
| Добавить проверку внутрь `_wait_for_resume_windows` | Чинит симптом, оставляет дублирование условия в двух местах; следующая платформенная ветка повторит ошибку |
| Тайм-аут на ожидание (например, 5 минут) и авто-продолжение | Меняет семантику паузы: пользователь ожидает, что загрузка стоит до его действия |
| Не показывать паузу в не-TTY вовсе (игнорировать запрос) | Запрос паузы в не-TTY невозможен физически, но флаг может быть выставлен программно; тихое игнорирование скроет ошибку конфигурации |

### Влияние на поведение

| Среда | Было | Стало |
|-------|------|-------|
| Windows + TTY | клавиша `r`/Enter | без изменений |
| Windows без TTY | **бесконечное зависание** | приглашение и продолжение по Enter (EOF на закрытом stdin завершает штатно) |
| Linux/macOS + TTY | клавиша `r`/Enter | без изменений |
| Linux/macOS без TTY | fallback на prompt | без изменений |

### Тесты

- Существующий `tests/test_pause.py::test_wait_if_paused_clears_flag_with_prompt_fallback` начинает проходить на Windows — он и есть основная проверка.
- Новый: `test_wait_if_paused_uses_key_backend_on_tty` — при `isatty → True` вызывается платформенный бэкенд (замоканный), `typer.prompt` не вызывается.
- Новый: `test_disable_interrupts_windows_wait` (только win32, `pytest.mark.skipif`) — `disable()` разрывает ожидание.

## D-2. Платформенно-независимые ассерты путей (GAP-CR-027)

### Проблема

`tests/test_history_import.py:46,52` сравнивают `file_path` со строкой с прямым слэшем; на Windows `HistoryStore` сохраняет нативный путь с обратным.

### Решение

Сравнивать через `Path`, а не через подстроку:

```python
# tests/test_history_import.py
from pathlib import Path

assert Path(first["file_path"]) == Path("downloads/first.mp4")
...
assert Path(second["file_path"]) == Path("downloads/second.mp4")
```

`Path("downloads/first.mp4")` на Windows нормализуется в `WindowsPath('downloads/first.mp4')` и сравнивается с `WindowsPath('downloads\\first.mp4')` как равный — сравнение идёт по частям пути, а не по строке.

Продукт **не меняется**: нативное представление `file_path` — намеренное, путь показывается пользователю в `ytd history show` и должен быть пригоден для копирования в его оболочке. Это решение фиксируется комментарием в тесте, чтобы не «чинили» продукт при следующем падении.

### Профилактика

Пройти по остальным тестам на предмет строковых сравнений путей и заменить на `Path`-сравнения там, где они есть. Проверка выполняется поиском `endswith("` и `in str(` по `tests/`.

## D-3. Матрица платформ и таймауты в CI (GAP-CR-028)

### Решение

Две независимые правки: матрица ОС и защита от зависаний.

**1. Матрица платформ.** Тестовая джоба выполняется на обеих ОС, линт — один раз (он платформенно-независим):

```yaml
# .github/workflows/test.yml
jobs:
  test:
    runs-on: ${{ matrix.os }}
    strategy:
      fail-fast: false
      matrix:
        os: [ubuntu-latest, windows-latest]
    steps:
      - uses: actions/checkout@v4
      - uses: astral-sh/setup-uv@v6
        with:
          python-version: "3.14"
          enable-cache: true
      - name: Install dependencies
        run: uv sync --frozen
      - name: Run tests
        run: uv run pytest -q

  lint:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: astral-sh/setup-uv@v6
        with:
          python-version: "3.14"
          enable-cache: true
      - name: Install dependencies
        run: uv sync --frozen
      - name: Ruff lint
        run: uv run ruff check .
```

`fail-fast: false` — чтобы падение на одной ОС не скрывало результат другой.

**2. Защита от зависаний.** `pytest-timeout` в dev-группу и глобальный лимит на тест:

```toml
# pyproject.toml
[dependency-groups]
dev = [
  "pytest>=9",
  "pytest-timeout>=2.3",
  "ruff>=0.9",
]

[tool.pytest.ini_options]
timeout = 60
timeout_method = "thread"
```

60 секунд с запасом покрывают самый медленный текущий тест (полный прогон — ~38 с на все 96), при этом зависание падает с трассировкой вместо блокировки джобы.

**Порядок обязателен:** матрица включается **после** закрытия BL-1101 и BL-1102, иначе первая же сборка на `windows-latest` повиснет или упадёт. Таймаут можно вводить раньше — он превратит зависание в понятное падение.

### Стоимость

Время CI примерно удваивается (Windows-раннеры медленнее). Для проекта такого размера (полный прогон ~40 с) это приемлемо.

## D-4. Декомпозиция `execute_download` (GAP-CR-029)

### Цель

Свести `execute_download` к подготовке контекста и диспетчеризации; вынести сценарии в отдельные модули; заменить замыкания явными параметрами.

### Целевая структура

```
ytd/workflows/
├─ download_command.py      execute_download: подготовка + диспетчер (~150 строк)
├─ context.py               DownloadContext, DownloadTotals  (новый)
├─ url_sources.py           чтение --urls-file, автодетект и выбор плейлиста (новый)
├─ info_fetch.py            fetch_info_with_prompt как функция от контекста (новый)
├─ single_video.py          сценарий одиночного видео (новый)
├─ playlist_unified.py      интерактивный плейлист, режим 1 (новый)
├─ playlist_per_video.py    интерактивный плейлист, режим 2 (новый)
├─ playlist_batch.py        неинтерактивный плейлист с паузами (новый)
├─ playlist_entries.py      без изменений
├─ entry_download.py        без изменений
├─ history_prompts.py       без изменений
└─ network.py               без изменений
```

### Контекст вместо замыканий

```python
# ytd/workflows/context.py
from __future__ import annotations

from dataclasses import dataclass, field
from logging import Logger
from pathlib import Path

from ..downloader import Downloader
from ..pause import PauseController
from ..types import AppConfig


@dataclass(slots=True)
class DownloadContext:
    """Всё, что нужно любому сценарию загрузки. Заменяет захват переменных замыканиями."""

    cfg: AppConfig
    logger: Logger
    dl: Downloader
    dry_run: bool
    interactive: bool
    verbose: bool
    history_available: bool
    pause_controller: PauseController | None
    auto_detect_playlists: bool
    playlist_items: str | None
    output_dir: Path


@dataclass(slots=True)
class DownloadTotals:
    """Агрегированные итоги; заменяет `nonlocal failed` и ручные счётчики."""

    total_files: int = 0
    failed: int = 0

    def merge(self, other: "DownloadTotals") -> None:
        self.total_files += other.total_files
        self.failed += other.failed

    def exit_code(self, *, dry_run: bool) -> int:
        if dry_run:
            return 0
        if self.failed == 0 and self.total_files > 0:
            return 0
        if self.failed > 0 and self.total_files > 0:
            return 2
        if self.failed > 0:
            return 1
        return 2
```

Каждый сценарий получает единую сигнатуру:

```python
def run(ctx: DownloadContext, url: str, decision: HistoryDecision) -> DownloadTotals: ...
```

`fetch_info_with_prompt` становится обычной функцией `fetch_info(ctx, url, *, title_hint, allow_skip, skip_message)` — её можно тестировать отдельно, подсовывая фейковый `Downloader`.

### Диспетчер

```python
# ytd/workflows/download_command.py (после рефакторинга)
for url, decision in zip(urls, decisions, strict=True):
    scenario = select_scenario(ctx, url)      # чистая функция, легко тестируется
    totals.merge(scenario(ctx, url, decision))
```

`select_scenario` заменяет каскад `if interactive / effective_playlist / pause_controller` и флаг `skip_post_processing`: сценарий выбирается **один раз** и сам отвечает за весь свой путь, поэтому «провалиться» в общий путь после поштучной загрузки структурно невозможно. Это устраняет класс дефекта doublesave на уровне архитектуры, а не флагом.

### Поэтапная миграция

Каждый этап — отдельный коммит с зелёным прогоном тестов:

| Этап | Содержание | Проверка |
|------|-----------|----------|
| 1 | `context.py`: `DownloadContext`, `DownloadTotals`; `execute_download` строит контекст, но логика не двигается | тесты зелёные, поведение не изменилось |
| 2 | `url_sources.py` + `info_fetch.py`: вынести чтение файла ссылок, автодетект/выбор плейлиста, `fetch_info` | новые unit-тесты на выбор плейлиста и парсинг файла |
| 3 | `single_video.py`: вынести ветку одиночного видео (интерактив и общий путь) | `tests/test_cli.py`, `tests/test_interactive_config.py` |
| 4 | `playlist_unified.py`, `playlist_per_video.py` | `tests/test_playlist_regression.py` |
| 5 | `playlist_batch.py` + `select_scenario`; удалить `skip_post_processing` | полный прогон + ручная проверка на реальном плейлисте |
| 6 | Свести `execute_download` к подготовке и диспетчеру; обновить `DEVELOPMENT.md` | ревью размера файлов |

### Критерий эквивалентности

Существующие тесты не переписываются под новую структуру (кроме путей импорта, если понадобятся). Зелёный `tests/test_playlist_regression.py`, `tests/test_cli.py`, `tests/test_interactive_config.py` — доказательство сохранения поведения. Дополнительно фиксируются exit-коды и текст итоговых сообщений: они входят в контракт CLI.

### Что осознанно не делаем

- Не вводим слой сервисов/плагинов из `devplan` — это отдельная фича, а не рефакторинг.
- Не меняем `process_playlist_entries` и `download_entry_with_retry`: они уже сфокусированы и переиспользуются.

## D-5. Мёртвая ветка опроса истории (GAP-CR-030)

### Решение: удалить

```python
# было
decision = preflight_decision
if decision is None:
    decision = prompt_history_decision(...)

# станет
decision = preflight_decision
```

Обоснование выбора «удалить», а не «реализовать»:

1. Preflight-опрос (`download_command.py:273`) уже спрашивает пользователя по каждому URL **до** начала загрузок — это осознанный UX: все вопросы задаются пачкой в начале, дальше процесс идёт без прерываний.
2. Повторный опрос по резолвнутому `history_video_id` означал бы второй вопрос про тот же URL после уже полученного ответа — регресс UX.
3. Для элементов плейлиста уточнённый опрос по реальному `video_id` уже выполняется в `process_playlist_entries:80`, то есть сценарий, ради которого ветка задумывалась, покрыт.

Сопутствующе: если после удаления `history_video_id` на этом пути становится неиспользуемой, переменная удаляется вместе с ветками её уточнения (`:379`, `:778`) — ruff (`F841`) подтвердит отсутствие мёртвых присваиваний. Уточнение `history_video_id` внутри плейлистных сценариев сохраняется.

Работа выполняется в рамках этапа 3–5 из D-4, чтобы не править один и тот же участок дважды.

## D-6. Локальный файл ссылок (GAP-CR-031)

### Решение

1. Снять файл с отслеживания, сохранив его на диске у пользователя:

   ```bash
   git rm --cached urls.local.txt
   ```

2. Активировать правило в `.gitignore` (строка 68) и расширить его на все локальные списки:

   ```
   # Local URLs files (do not commit real links)
   urls.local.txt
   urls.*.local.txt
   ```

3. Добавить безопасный шаблон `urls.example.txt` — только формат и синтетические примеры, без реальных ссылок:

   ```
   # Скопируйте в urls.local.txt и добавьте свои ссылки.
   # Одна ссылка в строке; строки, начинающиеся с #, игнорируются.
   # https://www.youtube.com/watch?v=VIDEO_ID
   # https://vk.com/video-00000000_000000000
   ```

4. Упомянуть в README рядом с примером `--urls-file`: рабочий файл локальный и не коммитится.

### Про историю коммитов

Ссылки остаются в прошлых ревизиях. Возможные варианты:

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| **Оставить как есть** (рекомендуется по умолчанию) | Ничего не ломается; ссылки не содержат секретов | Ссылки остаются доступны в истории |
| `git filter-repo` + force-push | История очищается | Переписывает все SHA, ломает форки/клоны/PR; требует пересоздания веток |

Решение принимает владелец репозитория. Дизайн **не** предполагает автоматического переписывания истории: это необратимая операция с внешними последствиями. В задаче BL-1107 пункт про историю оформлен как отдельный чекбокс с явным подтверждением.

## D-7. Синхронизация документации (GAP-CR-032, GAP-CR-033)

│  ├─ interactive.py
│  ├─ downloader.py
│  ├─ config.py
│  ├─ history/
│  └─ ...
├─ tests/
├─ docs/
└─ logs/                     # создаётся при первом запуске (в git — только .gitkeep)

Каталоги `downloads/` и `data/` создаются автоматически при первом запуске
согласно `output`, `history_db` и `save_metadata` из конфигурации.

## Порядок внедрения

Зависимости между задачами определяют порядок:

```
BL-1101 (пауза/Windows) ─┐
BL-1102 (тест путей)     ├─→ BL-1103 (матрица CI)
BL-1104 (pytest-timeout) ─┘        │
                                   ↓
BL-1107 (urls.local)   независимо  │
BL-1105 (декомпозиция) ────────────┴─→ включает BL-1106
BL-1108, BL-1109 (docs) независимо
```

| Шаг | Задачи | Почему в этом порядке |
|-----|--------|------------------------|
| 1 | BL-1104, BL-1101, BL-1102 | Сначала сделать прогон тестов завершаемым и зелёным на Windows |
| 2 | BL-1103 | Матрицу CI включаем только на зелёном Windows-прогоне |
| 3 | BL-1107 | Быстро, независимо, снимает вопрос приватности |
| 4 | BL-1105 (+BL-1106) | Крупный рефакторинг — под защитой уже работающего двухплатформенного CI |
| 5 | BL-1108, BL-1109 | Документация актуализируется после того, как код принял финальный вид |

## Сводный тест-план

| Изменение | Проверка |
|-----------|----------|
| D-1 | `tests/test_pause.py` целиком на Windows и Linux; новые тесты бэкенда и `disable()`; ручная проверка `p`/`r` на реальной загрузке |
| D-2 | `tests/test_history_import.py` на обеих ОС |
| D-3 | Зелёные джобы `test (ubuntu-latest)`, `test (windows-latest)`, `lint`; искусственно зависший тест падает по таймауту |
| D-4 | Полный прогон после каждого этапа; неизменность exit-кодов (0/1/2) и текстов итоговых сообщений; ручной прогон плейлиста в режимах 1 и 2 и в неинтерактивном режиме с паузами |
| D-5 | `ruff check .` без `F841`; регрессионные тесты истории |
| D-6 | `git ls-files urls.local.txt` пусто; `git status` не показывает локальный файл как untracked-шум |
| D-7 | Ревью документов; отсутствие ссылок на несуществующие каталоги; параллельность EN/RU |

Общий критерий готовности релиза Maintenance 1.2: полный `pytest` завершается и зелёный на Windows и Linux **без** `--deselect`, `ruff check .` чист, все BL-11xx закрыты или явно перенесены с обоснованием.

## Риски и их снижение

| Риск | Вероятность | Влияние | Снижение |
|------|-------------|---------|----------|
| Декомпозиция (D-4) ломает нюанс поведения, не покрытый тестами | средняя | высокое | Поэтапные коммиты, эквивалентность через regression-тесты, ручной прогон реального плейлиста перед закрытием |
| Windows-джоба в CI оказывается нестабильной (кодировки, временные файлы) | средняя | среднее | `fail-fast: false`; при плавающих падениях — сначала диагностика, не отключение джобы |
| Глобальный таймаут 60 с ложно роняет медленный тест на слабом раннере | низкая | низкое | Точечный `@pytest.mark.timeout(...)` вместо снижения планки для всех |
| Удаление ветки D-5 уберёт задуманный, но не реализованный сценарий | низкая | низкое | Обоснование зафиксировано в дизайне; при необходимости возвращается как отдельная фича с UX-обоснованием |
| `git rm --cached` воспринимается как потеря файла | низкая | низкое | Файл остаётся на диске; в задаче явно указано, что удаляется только отслеживание |
